# Contribuir a Aluvo

Gracias por ayudar a mejorar nuestros proyectos. Estas pautas ofrecen un punto de partida; las instrucciones del repositorio en el que trabajes tienen prioridad.

## Antes de comenzar

1. Lee el README del proyecto y revisa sus instrucciones de instalación y uso.
2. Busca issues y pull requests relacionados para aprovechar el contexto existente.
3. Para cambios de alcance amplio, abre primero una propuesta que explique el problema y el resultado esperado.

## Reportar un error

Usa la plantilla de errores del repositorio e incluye pasos para reproducir el problema, resultado esperado, resultado observado y versiones relevantes. Comparte un ejemplo pequeño cuando sea posible.

Antes de adjuntar capturas, datos o registros, elimina contraseñas, tokens, datos personales y cualquier información que no deba hacerse pública.

## Proponer una mejora

Describe qué necesidad resuelve, quién la utilizaría y cómo se comprobaría que funciona. Explica las alternativas consideradas y las limitaciones conocidas.

## Preparar un cambio

- Trabaja en una rama con un nombre que describa el objetivo.
- Mantén el cambio enfocado y sigue las convenciones existentes del proyecto.
- Actualiza la documentación cuando cambie el uso, la configuración o el comportamiento.
- Ejecuta las comprobaciones indicadas por el proyecto y documenta lo que verificaste.
- Abre un pull request con un resumen claro, referencia al issue relacionado y evidencia de validación.

Si no pudiste ejecutar una comprobación, indica cuál y por qué.

## IA y automatización

En cambios relacionados con IA, registra los modelos y versiones relevantes, los criterios de evaluación y las limitaciones observadas. Usa ejemplos que se puedan compartir sin exponer información privada.

En automatizaciones, describe los permisos y sistemas afectados, los efectos de ejecutar el flujo y cómo se recupera de errores cuando corresponda.

## Revisión

Explica tus decisiones con contexto y mantén las conversaciones centradas en el trabajo. Las preguntas, sugerencias y revisiones deben facilitar que otras personas comprendan y mantengan la solución.
